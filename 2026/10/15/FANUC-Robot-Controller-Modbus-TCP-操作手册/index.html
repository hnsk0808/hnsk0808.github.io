FANUC Robot Controller Modbus TCP 操作手册

本文翻译自FANUC Robot Controller Modbus TCP Interface Manual

原文链接：https://studylib.net/doc/25959495/b-82844en-01

简介

Modbus TCP 接口可通过以太网网络，与其他支持 Modbus TCP 的设备进行 I/O 数据交互。
机器人上的 Modbus TCP 选件仅作为服务端（从站 slave），因此只能和客户端（主站 master）设备交换 I/O 信号。
Modbus TCP 基于 TCP/IP 协议，采用客户端 - 服务端模型。Modbus TCP 可配置为交换机器人所支持的全部 I/O 信号。Modbus TCP 规范由 Modbus-IDA 组织维护。

以太网属于非确定性网络，Modbus TCP 不保证时序。
若在设定的时限内没有收到 I/O 交互报文，机器人 Modbus TCP 服务端将会超时并上报故障（除非关闭超时功能）。
良好的网络规划与拓扑结构，对于实现两台设备间高速、可靠的 Modbus TCP 通信至关重要。

系统概述

Modbus 概述

机器人 Modbus TCP 服务器最多支持4 路并发 Modbus TCP 连接。这些连接分为两类连接池：优先连接池与非优先连接池。默认情况下，所有连接均为非优先连接。

可通过指定 Modbus TCP 客户端 IP 地址，将最多 2 条连接设置为优先连接。也就是说：只有配置了对应 IP 地址的设备，才能作为 Modbus TCP 客户端，通过优先连接接入机器人；其他客户端设备无法使用优先连接。

任意 Modbus TCP 客户端设备都可以接入非优先连接，除非机器人中将非优先连接池的大小设为 0。
若所有可用的非优先连接已被占用，此时又有新的 Modbus TCP 客户端尝试接入非优先连接池，则最早建立的那条非优先连接会被断开，新的连接请求将被受理。

Modbus TCP 接口在机器人 I/O 映射中对应：96 号机架，1 号槽位。
可通过 Modbus TCP 映射任意数量 I/O，上限为机器人支持的最大 I/O 点数。

良好的网络规划是保证通信可靠的关键。必须避免或妥善处理过量网络流量与网络冲突。

离散输入与输入寄存器

离散输入从地址0开始访问。例如：指令“读取离散输入4”，会访问机器人第5路数字输出点（DO[5]），如图2.1中斜纹区域所示。

输入寄存器同样从地址0开始访问。例如：指令“读取输入寄存器2”，会以寄存器形式访问第3组共16个数字输出点（DO[33]~DO[48]），如图2.1中横纹区域所示。

注意：读取Modbus寄存器时，机器人返回数据为大端格式；输出点位编号顺序：从最低位（右侧）到最高位（左侧），见图2.1。

这两张数据表地址相互重叠，意味着：

读取离散输入0~15，等效于读取输入寄存器0；

此外，读取离散输入16~31，等效于读取输入寄存器1，以此类推。

在图 2.1 中，斜纹标记的输出点代表读取离散输入 4这条请求所返回的输出点位。
数据映射表里的横纹区域，代表读取输入寄存器 2这条请求会返回的、包含 16 个点位的寄存器。

线圈与保持寄存器

线圈从地址 0开始访问。例如，指令 “写线圈 4” 会访问机器人第 5 路数字输入点，如图 2.2 斜纹区域所示。

保持寄存器同样从地址 0开始访问。例如，指令 “写寄存器 2” 会访问第 3 组共 16 路数字输入点（DI [33]~DI [48]），如图 2.2 横纹区域所示。
写入保持寄存器时，线圈以大端格式写入；输入点位编号顺序：从最低位（右侧）到最高位（左侧），见图 2.2。

这两张数据表地址相互重叠，意味着：

写入线圈 0~15，等效于写入保持寄存器 0；

此外，写入线圈 16~31，等效于写入保持寄存器 1，以此类推。

在图 2.2 中，斜纹标记的输入点代表写线圈 4请求所写入的输入点位。
数据映射表的横纹区域代表写寄存器 2请求将要写入的、包含 16 个点位的寄存器。

机器人数字输出（DO）也可以通过只读的 Modbus 保持寄存器访问，起始地址为 10000。
例如，指令 “读取寄存器 10002” 会访问第 3 组共 16 路数字输出点（DO [33]~DO [48]），如图 2.2 横纹区域所示。

读取保持寄存器时，数据采用大端格式；输出点位编号顺序：从最低位（右侧）到最高位（左侧），见图 2.3。

在图 2.3 中，数据映射表里的横纹区域代表读取输入寄存器 2请求所返回的、包含 16 个点位的寄存器。

通过保持寄存器同时访问机器人数字输入与数字输出，可以使用 Modbus 功能码 23：读写寄存器（ReadWrite Registers）。Modbus 客户端可通过单条 Modbus 请求，同时读取和写入机器人数字 I/O 信号。

0 基地址与 1 基地址

Modbus 地址为0 基（从零开始编号），而机器人本体 I/O 地址为1 基（从 1 开始编号）。这点容易让部分用户混淆。
例如：访问机器人数字输入 1（DI [1]）时，Modbus 客户端应配置访问线圈 0。

不过机器人 Modbus 软件也支持在 Modbus 协议层启用 1 基地址模式。
当系统变量 $MODBUSTCP.$BASEZERO 设置为 FALSE 时，强制启用 1 基地址。此时 Modbus 客户端需要向线圈 1写入，才能控制机器人 DI [1]；若向线圈 0 写入，会触发 Modbus**非法地址（Illegal Address）**报错。

本文档中所有示例，均默认使用0 基地址。

支持的Modbus功能码

机器人Modbus TCP服务端支持下表所列Modbus功能。

表2.3 Modbus功能列表

十进制码 十六进制码 功能名称
01 0x01 Read Coils 读线圈
02 0x02 Read Discrete Inputs 读离散输入
03 0x03 Read Holding Registers 读保持寄存器
04 0x04 Read Input Registers 读输入寄存器
05 0x05 Write Single Coil 写单个线圈
06 0x06 Write Single Register 写单个寄存器
16 0x10 Write Multiple Registers 写多个寄存器
23 0x17 Read/Write Multiple Registers 读写多个寄存器

简要说明

  • 01(0x01)：读线圈 → 读取/控制DI信号
  • 02(0x02)：读离散输入 → 读取DO信号
  • 03(0x03)：读保持寄存器，可读取DI状态，也可读10000起始段的DO
  • 04(0x04)：读输入寄存器
  • 05(0x05)：写单个线圈，单点控制DI
  • 06(0x06)：写单个保持寄存器，一次性写16个DI
  • 16(0x10)：批量写保持寄存器
  • 23(0x17)：一次报文同时完成寄存器读+写，适合一边读DO、一边下发DI控制信号

以太网连接与IP地址分配

机器人要作为Modbus TCP节点工作，必须配置有效的IP地址与子网掩码。以太网接口和TCP/IP配置的详细说明，请参阅《Internet Options Setup and Operations Manual（互联网选件设置与操作手册）》。

以太网接口支持10Mbps、100Mbps速率，支持半双工与全双工通信。默认情况下，两个网口都会自动协商，建议连接到支持100Mbps全双工的交换机。如果只在一端（机器人或交换机）开启自动协商，另一端不开启，很容易出现双工模式不匹配，会引发严重通信故障。

主CPU板RJ45接头旁的LED指示灯，可用来确认链路是否建立。LED的详细说明，请参阅手册附录“Diagnostic Information（诊断信息）”。

IP地址可通过以下两种方式配置：

  • 在机器人示教器上手动配置 — 参考《互联网选件设置与操作手册》中“Setting Up TCP/IP（TCP/IP设置）”章节
  • DHCP（动态主机配置协议） — 参考手册“Dynamic Host Configuration Protocol（动态主机配置协议）”章节

注意
DHCP属于可选软件组件。使用Modbus TCP时，强烈建议使用静态IP或者永久租期IP地址。

可以配置其中一个以太网端口，也可两个端口同时启用Modbus TCP。注意：如果要同时使用两个网口，必须将它们配置在不同子网。详细参考手册“Setting Up TCP/IP（TCP/IP设置）”章节。

注意
在执行本手册中的各项功能前，请确保所有Modbus TCP节点的IP地址配置正确。可使用PING工具验证基础连通性，更多信息见6.3节。

Modbus TCP 服务端配置

概述

机器人最多支持4 路 Modbus TCP 连接。这类连接通常对接单元控制器或 PLC，用于交换工作站接口 I/O 数据。必须加载 Modbus TCP 选件，才能启用该功能。

配置

Modbus TCP界面分为两个区域：状态区（Status） 和配置区（configuration）。
状态区仅包含一项：从站状态（Slave Status），该字段为只读。
配置区包含6个用户可配置字段。对配置字段做的任何修改，必须重启电源才能生效。表3.1描述了Modbus TCP界面的所有项目。请按照流程3-1来配置Modbus TCP从站。

表3.1 Modbus界面项目

字段名称 说明
Slave Status（从站状态） 从站状态字段显示为 RUNNING（运行中）或 IDLE（空闲）。 RUNNING：正在与Modbus TCP主站进行I/O数据交互； IDLE：当前无I/O数据交互。
Number of Connections（连接数量） 连接数量字段用于指定从站可同时建立的Modbus TCP连接数。取值范围0～最大4路；设为0可完全关闭机器人Modbus从站功能。 按照Modbus TCP协议规范：当新连接请求到来、且无空闲连接资源时，系统会关闭最旧的连接，再接受新连接。上电后首次发生此场景，会触发PRIO-494警告报警。
Timeout（超时时间） 超时字段定义空闲Modbus TCP连接的超时时间（单位：毫秒）。 若在该超时时间内没有收到来自主站的报文，从站会判定网络连接丢失/断开，关闭全部连接并上报超时报警。此字段设为0可关闭超时检测。
Error Severity（错误等级） 错误等级字段定义Modbus TCP报警的严重级别。可通过F4【CHOICE】按键设置为 STOP（停机）、WARN（警告）或 PAUSE（暂停）。
Keep Input on Timeout（超时保持输入） 超时保持输入字段用于定义发生超时时输入信号的处理方式。 设为FALSE：超时发生后，所有Modbus输入置0； 其余情况：输入保持超时前的状态不变。
Input Words（输入字数量） 输入字字段用于分配数字输入的容量。此处1个字 = 16位。例如配置4个字，则分配64点数字输入，分配至机架96，插槽1。所有连接到机器人Modbus从站的主站，均可读写该数字输入数据。
Output Words（输出字数量） 输出字字段用于分配数字输出的容量。此处1个字 = 16位。例如配置4个字，则分配64点数字输出，分配至机架96，插槽1。所有连接到机器人Modbus从站的主站，均可读取该数字输出数据。

流程3.1 配置Modbus TCP从站

  1. 按下【MENUS】菜单键。
  2. 选择【I/O】。
  3. 按下F1【TYPE】，然后选择Modbus TCP，界面将显示类似下方的画面。

  1. 依次选中下面各项，按需求进行参数设置（参考表3.1）
  • Number of Connections（连接数量）
  • Timeout（超时时间）
  • Error Severity（错误等级）
  • Keep Input on Timeout（超时保持输入）
  • Input Words（输入字数量）
  • Output Words（输出字数量）
  1. 关闭控制器电源，然后重新上电。

优先连接

Modbus TCP服务端支持优先连接。最多可以指定2条连接作为优先连接，配置方式是填写Modbus TCP客户端的IP地址。
这表示：除了该IP对应的设备之外，其他Modbus TCP客户端设备无法占用这条优先连接。并且机器人Modbus TCP服务端不会主动关闭优先连接，除非客户端主动断开连接，或者发生超时。

任意Modbus TCP客户端设备都可以接入非优先连接（未标记为优先的连接）。当所有可用非优先连接全部被占用，又有新客户端尝试接入非优先连接池时，系统会关闭现存最早建立的非优先连接，接受新连接请求。上电后首次出现该场景时，会触发PRIO-494警告报警。

默认情况下，所有连接均为非优先连接。
可通过设置下面一个或两个系统变量（填写合法IP地址或主机名）来配置优先连接：

  • $MODBUSTCP.$PRIO1
  • $MODBUSTCP.$PRIO2

举例：假设有一台PLC IP：192.168.1.11，一台HMI设备IP：192.168.1.22。
我们希望PLC的连接作为优先连接，HMI使用非优先连接。
需要将“Number of Connections（连接数量）”设置为2；
同时设置 $MODBUSTCP.$PRIO1 = "192.168.1.11"；
最后根据PLC或HMI中较快的扫描周期，合理设置“Timeout（超时时间）”参数。

在上面这个例子中，一共配置了2条Modbus TCP连接，其中一条设置为PLC的优先连接。由于仅配置了1条优先连接，第二条连接默认为非优先连接，可供任意Modbus TCP客户端（包括HMI设备）使用。

I/O 配置

概述

本章介绍如何将Modbus TCP I/O映射到机器人内部的数字信号与组信号，从而在机器人程序内使用Modbus TCP I/O信号。同时也介绍Modbus TCP及I/O配置的备份与恢复操作流程。

在机器人上映射I/O

Modbus TCP I/O可以映射到数字I/O或组I/O。原理和机器人上其他I/O点映射类似：机架（rack）、槽位（slot）、起始点编号用于把物理I/O映射为I/O映射表里的逻辑I/O。Modbus TCP I/O固定使用机架96，槽位1。
使用流程411在机器人上完成I/O映射。

流程4.1 在机器人上映射I/O

  1. 按下【MENUS】菜单键
  2. 选择【I/O】
  3. 按F1【TYPE】，选择Digital（数字信号）或Group（组信号）
  4. 按F2【CONFIG】
  5. 将Range（范围）设置为合适的值
  6. 机架设为96，槽号设为1，并按需求设置起始点

备注
如需更多I/O配置相关信息，请查阅对应应用的《设置与操作手册》中输入/输出(I/O)设置章节。

在部分应用软件中，控制器上电时会自动完成I/O配置。系统变量 $IO_AUTO_CFG 用于控制数字I/O的自动配置行为。

Modbus TCP的备份与恢复

有两个文件保存Modbus TCP与I/O映射配置信息：

  • DIOCFGSV.IO：保存通用I/O配置以及全部I/O映射（例如Modbus TCP和数字信号、组信号之间的映射关系）
  • SYSMBUS.SV：保存Modbus TCP专属配置

可使用流程4-3手动备份这两个文件。
流程4-4用于完整应用程序备份，会同时包含DIOCFGSV.IO和SYSMBUS.SV。

流程4-3 手动备份文件

  1. 选择文件保存的默认存储设备
    a. 按下【MENUS】
    b. 选择【File】文件
    c. 按F5【UTIL】，选择【SET DEVICE】设置设备
    d. 选中你想要保存文件的设备
  2. 保存 DIOCFGSV.IO
    a. 按下【MENUS】
    b. 选择【I/O】
    c. 按F1【TYPE】，选择DIGITAL数字信号
    d. 按FCTN功能键
    e. 选择Save保存，将DIOCFGSV.IO保存至默认设备
  3. 保存 SYSMBUS.SV
    a. 按下【MENUS】
    b. 选择【I/O】
    c. 按F1【TYPE】，选择Modbus TCP
    d. 按FCTN功能键
    e. 选择Save保存，将SYSMBUS.SV保存至默认设备

流程4-4 执行完整应用备份

  1. 选择文件保存的默认存储设备
    a. 按下【MENUS】
    b. 选择【File】文件
    c. 按F5【UTIL】，选择【SET DEVICE】设置设备
    d. 选中你想要保存文件的设备
  2. 按F4【BACKUP】备份，选择“All of above”全部内容

Modbus TCP 规范指南

良好的网络设计对可靠运行至关重要。需要特别留意布线规范，以及会影响线缆系统和设备的环境条件；同时要管控网络流量，避免带宽与设备资源浪费。

布线与环境注意事项：

  • 使用5类及以上双绞线，满足100‑BaseTX以太网标准，适配应用场景与现场环境；根据工况选择屏蔽或非屏蔽双绞线。
  • 严格遵守布线规范，例如交换机到设备的线缆最大长度（100米）。
  • 线缆弯曲半径不可超过该线缆规格推荐限值。
  • 使用适配现场环境的连接器。除普通开放式RJ45外，适用场景应选用工业以太网接头，例如具备IP65、IP67防护等级的连接器。
  • 线缆布线远离电气、磁场干扰源；若必须交叉，采用90°正交走线，降低以太网线路上的感应噪声。

网络流量管理要点：

  • 限制冲突域，控制或消除网络冲突。
  • 限制广播域，管控广播流量。
  • 通过智能路由管控组播流量。
  • 高负载严苛应用场景下，采用QoS（服务质量）技术。

冲突是传统以太网的常见问题，使用交换机（而非集线器）搭配全双工连接可彻底避免冲突。以太网I/O网络必须使用交换机+全双工连接，可将冲突域缩小至单台设备，从而杜绝冲突。

机器人接口默认自动协商，协商出最优连接速率，一般为100Mbps、全双工。可手动指定机器人的连接速率与双工模式（参考《互联网选项设置与操作手册》中“TCP/IP设置”章节）。

⚠️ 注意：通信两端速率、双工模式必须保持一致，或者两端都开启自动协商。如果仅单侧开启自动协商，极易发生双工模式不匹配，引发严重故障。

机器人RJ45接头旁的LED灯用于确认链路连接状态（LED详情请查阅《互联网选项设置与操作手册》附录“诊断信息”）。也可以按照流程5-1，在TCP/IP主机通信状态画面查看链路状态。

流程5-1 校验链路状态

  1. 按下【MENUS】菜单
  2. 选择【Setup】设置
  3. 按F1【TYPE】，选择【Host Comm】主机通信
  4. 选择【TCP/IP】
  5. 按F3【PORT】切换到对应网口（1号口或2号口）
  6. 按【NEXT】，再按F2【STATUS】查看状态

广播流量：子网内所有节点都要接收广播报文，部分场景下还需要应答。过量广播流量会占用大量网络带宽，消耗所有节点设备资源。
广播域：必须接收全部广播报文的设备范围（一般为整个子网）。
发那科机器人推荐：使用独立子网或者高端交换机支持的VLAN（虚拟局域网），把广播域限制在控制设备范围内（如Modbus TCP节点）。

如果Modbus TCP网络作为独立网络完全隔离，则不用考虑该问题；但当它接入更大的网络时，该点就非常关键。

QoS提供流量优先级调度机制。普通以太网默认所有数据包优先级均等；网络拥塞时，数据包会随机丢弃或延迟。QoS就是多种报文优先级处理技术的统称，包含：

  • MAC层（二层）优先级（IEEE 802.1p）
  • IP层（三层）优先级，基于源/目的IP地址
  • 传输层（四层）优先级，基于源/目的端口

这类QoS功能一般在网络基础设施设备（交换机）内实现，超出本手册的介绍范围。
对于对I/O通信确定性要求极高的复杂控制网络，建议启用QoS，同时需要满足：

  • 100Mbps通信速率
  • 全双工连接
  • 端口自动协商
  • 适配工况的环境指标（温度等）
  • 电源要求与冗余设计（例如支持24Vdc或120Vac，可配置第二路冗余电源）

备注1
如果网络中存在大量组播流量，交换机需要支持 IGMP Snooping（IGMP侦听，组播感知）。

备注2
如果该控制网络需要接入更大的网络，控制网络应当部署在独立VLAN或者独立子网内。可以在控制交换机上配置实现，也可以根据主网与控制交换机之间的接入方式来规划。

交换机产品示例

  • RJLinx ENHSAURR8：8口非网管型工业交换机
  • Telesyn AT-FS716：16口非网管型交换机
  • Cisco 2950-12：12口网管型交换机
  • Cisco 2955（2950的工业版）
  • Hirschmann MICE：模块化工业交换机
  • Phoenix Contact：网管/非网管型工业交换机
  • Interlink-BT SE-84x-E524：5口网管/非网管型工业交换机

诊断与故障排查

概述

校验网络连接有两种基础工具：

  • 以太网状态指示灯
  • PING工具

指示灯与PING工具属于基础检测手段，但可以有效判断设备能否在网络中通信。
如果LINK指示灯熄灭，或者PING请求超时，代表该设备的所有网络功能都无法正常工作。
更多以太网状态指示灯的内容见6.2节；PING工具相关内容见6.3节。

以太网状态指示灯

机器人RJ45网口上的以太网状态指示灯用于显示机器人的物理链路连接状态。绝大多数以太网交换机与其他设备也配有同类指示灯，用来指示物理层连接。

如果 LINK指示灯熄灭：代表以太网物理连接完全断开，通常原因是网线松动、断线或者接头接触不良。
机器人和交换机两端的速率、双工模式必须保持匹配。

以太网指示灯详细说明请查阅《互联网选项设置与操作手册》附录“诊断信息”。
自动协商、手动设置速率与双工模式的详细内容，参考该手册“TCP/IP配置”章节。

机器人默认开启自动协商，绝大多数场景下不要修改此默认配置。

PING工具

PING是一款网络工具：向指定IP地址发送探测请求，等待对方应答。这个请求本质就是询问：你能否收到我的报文？
目标设备收到请求后会回复应答包；发起端收到应答代表连通正常，无应答则判定超时。

PING是基础网络工具，Linux、Unix、Windows等多数操作系统自带，FANUC机器人系统也内置该工具。
就算设备自身不能主动发起PING（例如不带操作界面的Modbus TCP模块），也可以响应PING探测包。
机器人本体可使用PING去测试任意主机名或IP地址（步骤见流程6-1）；Windows电脑同样可以使用PING（步骤见流程6-2）。

流程6-1 在机器人上使用PING

  1. 按下 MENU（菜单）
  2. 选择 Setup（设置）
  3. 按F1，【TYPE】类型
  4. 选择 Host Comm（主机通信）
  5. 在协议列表中移动光标选中 PING，按下 ENTER
  6. 输入需要PING测试的节点名称或IP地址
  7. 按F2，PING执行测试

备注：示教器提示行会显示PING成功，或是请求超时。

流程6-2 在Windows电脑上使用PING

  1. 打开DOS命令提示符（CMD）
  2. 输入命令，替换成目标IP地址，回车执行

示例：PING 192.168.0.10
